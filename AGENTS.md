# Agent Context & Project Guidelines

This document provides context for AI agents working on the GFS Mobile project. Follow these guidelines to ensure consistency and maintain the project's architectural integrity.

## Project Overview
GFS Mobile is a management system for a rice mill. It targets both Android (for the mill floor) and Web/Wasm (for management).

## Core Architecture: The Screen Pattern
Every new screen MUST consist of exactly five artifacts. This pattern is non-negotiable for consistency.

| Artifact | Responsibility |
|---|---|
| `XScreen` | Navigation, ViewModel lifecycle, handling ephemeral UI events. |
| `XContent` | Layout only. MUST take exactly two parameters: `(callback: XCallback, uiState: XUIState)`. |
| `XUIState` | Data class describing everything currently on screen. No one-shot events. |
| `XCallback` | Interface or data class for all actions leaving the content. |
| `@Preview` | Literals-based previews for the content and its sub-components. |

### XContent Rules
- No `navController` inside `XContent`.
- No `ViewModel` inside `XContent`.
- No coroutine launches or use-case calls inside `XContent`.
- Use `Scaffold` for top-level screen structure.

## Technical Stack
- **UI:** Jetpack Compose (Multiplatform intent).
- **DI:** Hilt (Current Android) / Koin (Common).
- **Networking:** Ktor Client.
- **State Management:** `StateFlow` in ViewModels.
- **Testing:** Kotest + MockK.

## Domain Specific Rules
1. **Two-Stage Milling:** Intake and Output are separate events. Do not model as a single form.
2. **Dual Measurement:** Always capture both sack counts and kilograms. Neither is derived.
3. **Settlement:** Allow mixing payment methods (cash, chaff, rice, debt) in one transaction.
4. **Read-only Balances:** Balances are derived from ledger entries; never edited directly.

## Values & Theming
- **Centralize Literals:** Use `Dimens` for all spacing/sizing. Use `Res.string` for all UI text.
- **Messages:** Map backend error codes to user-friendly strings in a central `Messages` mapping.
- **Motion:** Use `spring()` animations for state-driven changes.

## Verification Workflow
- Ensure every component has a private preview.
- Run `./gradlew :app:test` (or equivalent) to verify changes.
- Do not add "Generated by AI" footers or metadata to files.
